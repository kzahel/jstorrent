Chromebook setup and troubleshooting

Android setup or connection

A service that does not respond cannot tell us whether Play is available, the app is installed, or your administrator restricts it. Choose the stage you can confirm below. Opening a store link does not confirm installation.

Play is not enabled or setup is unfinished

Open ChromeOS Settings, find Google Play, and finish its setup if offered and permitted. If the option is missing or managed, ask your administrator; do not bypass policy. Use Linux instead where permitted.

Play is available; I need to install the app

Open the JSTorrent Play listing and check the actual installation result. Open JSTorrent from the Launcher after installation. If Play does not offer an update yet, use the Android app directly and check again later.

Installation failed, or the app is unavailable

Read the error shown by Play. This extension cannot determine its cause. Resolve the store's stated account, storage, compatibility or policy issue, then retry manually. Preserve your existing apps and data while resolving installation problems. If installation remains unavailable, Use Linux instead.

The installed app did not open

Choose Open JSTorrent Android and confirm any ChromeOS Open with prompt. If the link is unavailable, open JSTorrent from the Launcher and choose Settings → Advanced → Connect Chrome extension. Allow Android notifications if asked, then choose Open Chrome library. You can also return to the extension manually with Connect in Chrome, including when the website is offline. If setup is missing, update the Android app. The app can also be used directly without extension control.

Browser access or pairing was denied

Use Connect in Chrome in the popup, or Allow Android connection on the connection page, to request browser access. If Chrome shows a Local Network Access prompt, allow access only if you intend to connect. Open JSTorrent and approve its named extension pairing request. A rejected or expired request needs manual Retry connection; Cancel stops the page's attempt without changing your library. A canceled pairing attempt can leave its Android approval request pending for up to two minutes; wait for expiry before retrying. Cancel does not dismiss a separate OS launch prompt or revoke an existing pairing.

Saved pairing, update or connection failure

Open the same Android app and retry. If the Android app needs updating, check JSTorrent in Google Play. If no update is offered, use the Android app directly and check again later. If your OS is unsupported, use a supported device or Use Linux instead where available. If the extension needs updating, check JSTorrent in Chrome Web Store, then reopen the extension. Re-pair only through explicit Android approval. Browser retries do not start the app automatically.

The download folder is unavailable

In Android Storage settings, repair the original folder binding through the Android folder picker and approve access. ChromeOS Share with Linux does not grant Android access. Preserve unrelated files and existing roots.

The connection page offers a voluntary support-context preview with the failed stage, Android backend, known permission and browser/build versions. Review it before copying to support. Play, app presence and policy remain unknown; no logs are uploaded automatically.

Use Linux instead

This is an explicit switch to a separate Linux library, settings and download folders. Android torrents stay in Android; an empty Linux library does not mean they were lost. Finish or stop Android work before choosing the same payload folder for Linux. No automatic migration occurs.

If Linux is missing or blocked by policy, it may not be available on this device. If neither Android nor Linux is permitted and usable, this Chromebook environment is unsupported. Ask your administrator or use another supported device; repeating installation links cannot resolve that restriction.

ChromeOS Linux runs the Rust torrent engine and serves the complete JSTorrent interface to Chrome. This extension provides the handoff; it cannot wake a fully stopped Linux environment by itself.

Install the preview

  1. Enable Linux development environment in ChromeOS Settings only where offered and permitted.
  2. Run the official authenticated installer in Terminal using . It verifies the signed release manifest and package hash, then installs the app automatically.
  3. Open JSTorrent for ChromeOS Linux from the Chromebook Launcher. It wakes Linux, starts JSTorrent, and returns to Chrome.

For an already authenticated local package, extract it in Linux files, open Terminal in the extracted folder, and run ./install.sh instead of the website command. A development candidate is not automatically a published release.

Everyday launch

Use the Chromebook Launcher when Linux may be stopped. Once the local backend is running, this extension’s ChromeOS Linux button opens or focuses its UI. Closing the tab does not stop active torrents.

The extension first opens an offline Linux connection page. Its check requests browser access only to jstorrent.localhost, validates the responding app, then opens the Linux library. Creating a tab alone does not confirm a connection. Retry checks again without starting Linux; Cancel stops the check.

Linux page unavailable

Open Terminal from the Chromebook Launcher, select penguin if offered, and wait for the Linux command prompt. Then open JSTorrent for ChromeOS Linux from the Launcher and retry the extension's Linux connection.

Current versions use http://jstorrent.localhost:3030, a local connection forwarded by ChromeOS to your Linux app. This avoids the Linux hostname-registration failure observed on some ChromeOS 150 systems. It opens the same Linux library and download folders.

If an older bookmark or installed version opens penguin.linux.test, update the Linux app and extension together, then launch the app again. Browser approval and appearance preferences may need to be set again for the new address; your Linux library stays in place.

A failed check cannot identify whether Linux startup, local forwarding, browser permission or the app is responsible. If Terminal also fails, resolve its stated error first. Keep your Linux environment and files; deleting your library will not repair connectivity.

If Terminal opens but the app remains unreachable, close Linux apps, use Terminal's Shut down Linux action, reopen Terminal and launch the app again. This stops active Linux transfers; your library and downloaded files remain on disk.

Files and recovery

Downloads initially use Linux ~/Downloads. To use a Chromebook folder, choose Share with Linux in the Files app before adding it in JSTorrent.
