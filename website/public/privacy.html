JSTorrent Privacy Policy

Updated October 10, 2026

This policy covers JSTorrent's Chrome extension, desktop application and Android app, and the JSTorrent website. Behavior varies between the legacy application and the replacement currently being qualified; the replacement's new optional hosted context remains disabled until deployment and verification are complete.

Local application data

Torrent metadata, download-folder access, settings and pairing information are stored locally. The native application owns downloaded files and the torrent engine. The extension connects to that application on your device. JSTorrent does not collect a general browsing history. Pairing credentials are local connection authority, not analytics identifiers.

The replacement keeps a random resettable installation identifier and coarse local counts of added torrents, completed downloads and foreground sessions. These values are separate from torrent names, hashes, paths, peers, trackers, logs and error text. They are pseudonymous, not anonymous: permitted requests can be correlated until the identifier is reset.

Update checks and network activity

Ordinary BitTorrent operation contacts peers and discovery services, which can observe network addresses and protocol information. Desktop update checks contact the update service with version and platform information. Depending on the version and disclosed statistics preference, an update check may also include the installation identifier. The replacement can preserve an older desktop installation's existing update identifier until you review the new disclosure. Once you review it, disabling statistics omits that identifier from update checks. Fresh installations do not send a new identifier before that review.

There is no continuous product analytics event upload or automatic crash-report upload in the replacement. This does not mean that update requests or user-opened websites send no data: ordinary HTTP requests expose network addresses and request information.

Feedback, uninstall surveys and the website

Feedback and uninstall pages embed Google Forms and use Cloudflare Web Analytics. Navigating to a page can expose URL context to browser history, website logs and referrers, the embedded form and website analytics before a form is submitted. Review the context shown by the application before opening a feedback page and review your response before submission.

The replacement currently sends only its accepted environment fields to feedback: platform and version, plus Android release and manufacturer/model where applicable. New optional installation identifier, days since first use and aggregate usage fields remain release-disabled. If enabled in a later verified release, they require the disclosed preference and can be omitted for a feedback navigation. The extension has its own local identifier and never adopts the native application's identity.

Older clients may construct different feedback context. Receiving pages accept only bounded known fields and render values as text. Filtering a page's display or form does not erase a URL already received by browser history or a website server.

Voluntary support reports and controls

Support diagnostics in the replacement produce a local, reviewable report of build, package and closed update-status facts. Preparing, copying or saving that report uploads nothing automatically. You choose whether to share it. Public issue reports and their attachments are public; review screenshots, logs and other attachments for private information before submitting.

Usage-statistics controls can disable permitted identifier/counter context; reset controls create a new product identifier and clear local counters. These actions do not delete downloaded content and cannot retract data previously sent to recipients. Website analytics and submitted Google Forms have their own recipient policies.

Contact

For privacy questions, use the JSTorrent issue tracker. Do not include private library data or credentials in a public issue.
